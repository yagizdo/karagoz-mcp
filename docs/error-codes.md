# Error codes

The set is closed. Any failure without a code of its own is reported as `INTERNAL`.

`ADB_NOT_FOUND`, `ADB_TIMEOUT` and `ADB_FAILED` come from every command that reaches adb, except `doctor`, which reports them in its output; `devices` reports them in `errors` when the other platform could be listed. The `SIMCTL_*` and `DEVICECTL_*` codes also come from the device listing that every command targeting a device runs on macOS ([Device selection](device-selection.md)); `devices` reports them inside `errors`.

| Code | Meaning | From |
| --- | --- | --- |
| `NO_COMMAND` | No command given. The message lists the commands. | all |
| `UNKNOWN_COMMAND` | The command name is not known. | all |
| `INVALID_ARGS` | Missing, extra, malformed or unknown arguments, an unknown key name or one with no iOS key (`BACK`; on an iPhone also a key that types no character, such as `DPAD_UP` or `F1`), an app path that is not an existing `.apk` or `.ipa` file or `.app` directory, an app for the other platform, a screenshot `--out` that does not end in `.png`, a malformed package name, a `--since` that is not Unix time in seconds, a `--lines` outside 1 to 999999999, a `--team` that is not a 10-character team ID, or no `--team` when Xcode lists several teams and not exactly one paid. | all |
| `ADB_NOT_FOUND` | No `adb` found. See [Requirements](requirements.md). | all that reach adb |
| `ADB_TIMEOUT` | adb did not answer in time: 10 s per call, 20 s for a `ui-tree` read, 10 s plus the duration for a long press or swipe, 30 s plus 1 s per started MB for `install`, 30 s for the start in `launch`. The message suggests `adb kill-server`; for `ui-tree` the cause is more often a stuck dump, and for `install` an install prompt on the phone, which the message names first. | all that reach adb |
| `ADB_FAILED` | adb exited with an error. The message is adb's stderr, or Node's error when adb printed nothing. For `launch`, `terminate` and `uninstall` it can also be the error the device command printed. For `logs`, logcat's own error text or output that is not whole log records. A device that disconnects mid-command ends here. | all that reach adb |
| `SIMCTL_NOT_FOUND` | No `simctl` found: Xcode is missing or was never opened, or `DEVELOPER_DIR` points somewhere without one. See [Requirements](requirements.md). | `screenshot`, `install`, `launch`, `terminate`, `uninstall` and `logs` on a simulator; device listing |
| `SIMCTL_TIMEOUT` | simctl did not answer in 30 s; for `install`, 30 s plus 1 s per started MB of the file (31 s for a `.app`). For `logs`, the read did not finish in 30 s; the message says what to pass to read less. | `screenshot`, `install`, `launch`, `terminate`, `uninstall` and `logs` on a simulator; device listing |
| `SIMCTL_FAILED` | simctl exited with an error, or printed something karagoz does not expect. The message is simctl's stderr, or Node's error when simctl printed nothing; for unexpected output, `unexpected simctl output:` and its first line. For `logs`, `log`'s own error, or output that is not `log show`'s records. | `screenshot`, `install`, `launch`, `terminate`, `uninstall` and `logs` on a simulator; device listing |
| `DEVICECTL_NOT_FOUND` | No `devicectl` found: Xcode older than 15, or never opened, or only the Command Line Tools, or `DEVELOPER_DIR` points somewhere without one. See [Requirements](requirements.md). | device listing |
| `DEVICECTL_TIMEOUT` | devicectl did not answer in 10 s; 30 s for a command on an iPhone (for `install`, plus 1 s for every started MB of the file), 120 s for installing the runner. For `launch` on an iPhone the message names an app held by a debugger. | `screenshot`, `ui-tree`, `install`, `launch`, `terminate`, `uninstall`, `logs --package`, `install-runner`, `uninstall-runner` on an iPhone; device listing |
| `DEVICECTL_FAILED` | devicectl exited with an error, or printed something karagoz does not expect. The message is devicectl's stderr, or Node's error when it printed nothing; for unexpected output, `unexpected devicectl output:` and its first line. For `screenshot` on an iPhone, any capture failure not listed under `DEVICE_NOT_READY`, such as no connection to the phone, a developer disk image that could not be mounted, or a second capture of the same phone while one runs. For `launch` and `terminate` on an iPhone, devicectl's description and the phone's reason. | `screenshot`, `ui-tree`, `install`, `launch`, `terminate`, `uninstall`, `logs --package`, `install-runner`, `uninstall-runner` on an iPhone; device listing |
| `NO_DEVICE` | No device connected and none named. On macOS the message also names booting a simulator. | all but `devices` and `doctor` |
| `DEVICE_NOT_FOUND` | The named device is not connected. | all but `devices` and `doctor` |
| `DEVICE_AMBIGUOUS` | More than one device and none named, or a name that matches more than one. | all but `devices` and `doctor` |
| `DEVICE_NOT_READY` | The device is `offline`, `unauthorized` or similar, or the simulator is `Booting` or `Shutting Down`, or its input service did not answer within 4 s (`tap`, `swipe`, `key` right after a boot), or for `screenshot` an iPhone that is not paired yet, has Developer Mode off, is no longer paired with this Mac, or is locked since it restarted; for `launch`, a locked iPhone; for `ui-tree`, `tap`, `swipe`, `text` and `key` also an iPhone not connected by USB cable, locked, with a developer it does not trust yet, a runner that did not start within 60 s (look at the phone: the passcode sheet for UI automation, or Enable UI Automation off), something else answering on the runner's port without this Mac's key, or another app holding that port; on a simulator of a Mac that never had Xcode 27, a runner that did not start within 60 s or a port another process took; for `logs`, an iPhone not connected by USB cable, one this Mac holds no pairing record for, or one that refuses this Mac's session. The message says what to do. | all but `devices` and `doctor` |
| `HELPER_FAILED` | On Android, `text`'s helper failed on the device (its error in the message). The iOS helper cannot run on this Mac: no Xcode selected, no `swiftc` (the Command Line Tools are not enough), a failed compile, a crash, an Xcode that changed a private interface karagoz uses, or input the simulator did not take (no automation session, typing that failed, no answer within 30 s). For the runner: no Apple account or team in Xcode (iPhone), a failed build (xcodebuild's error lines and the log path), xcodebuild failing to start the runner for a reason karagoz does not know (the log path), or an iOS that changed a private interface the runner uses; for input on an iPhone, an event the runner could not play (its message), no answer within 30 s plus the gesture or typing time, or a runner that closed the connection. For `logs` on an iPhone: usbmuxd unreachable, a failed TLS handshake, the phone's log service missing or refusing the archive, a stream that broke, ended early or sent nothing for 30 s, `tar` or `log` missing or failing (their own message), or `log show` not finished within 30 s. The message says which and what to do. | `ui-tree`, `tap`, `swipe`, `text`, `key` on a simulator or an iPhone; `text` on Android; `install-runner`; `logs` on an iPhone |
| `RUNNER_NOT_INSTALLED` | A command on an iPhone found no karagoz runner it can use: none is installed, the installed one was built by another karagoz or Xcode (or its build on this Mac was deleted), its profile does not include this iPhone, its profile expired, or a runner from an older karagoz is still answering (it signs nothing). The message names `karagoz install-runner --device <UDID>` and the MCP tool `install_runner`. | `ui-tree`, `tap`, `swipe`, `text`, `key` on an iPhone |
| `NOT_SUPPORTED` | The device is an iOS simulator with Xcode 26 or older on a Mac that once had Xcode 27: `'tap' on iOS simulators needs Xcode 27 or later` (`swipe`, `text` and `key` likewise). Or `text` with Xcode 27 or newer on a simulator older than iOS 27: `'text' on an iOS 26.2 simulator needs an iOS 27 or later simulator with Xcode 27 or later; ...`. Or `install-runner` or `uninstall-runner` on another device (`uninstall-runner` also takes a simulator on a Mac that never had Xcode 27): `device <id> is not an iPhone; karagoz's runner runs only on iPhones.` Or `screenshot` on an iPhone with a `devicectl` older than Xcode 27's: `'screenshot' on an iPhone needs Xcode 27 or later: ...`. Argument checks come first. | `tap`, `swipe`, `text`, `key` on a simulator with Xcode 26 or older on a Mac that once had Xcode 27; `text` on a simulator older than iOS 27 with Xcode 27 or newer; `screenshot` on an iPhone before Xcode 27; `install-runner` and `uninstall-runner` elsewhere |
| `CAPTURE_FAILED` | The screen could not be read: bad screenshot data, missing display info, a uiautomator failure, on iOS a read the helper could not finish or an app opened while the simulator's app accessibility was off (restart it), or on an iPhone a snapshot the runner could not take, no answer within 30 s, a runner that closed the connection, or for a `tap` or `swipe` in landscape no panel size from `devicectl`. The message says which. | `screenshot`, `ui-tree`, `tap --text/--id`; `tap`, `swipe` on an iPhone |
| `AUTOMATION_BUSY` | Another UiAutomation client holds the device; on a simulator, a UI test holds automation mode. | `ui-tree`, `tap --text/--id`; `text` on a simulator |
| `WRITE_FAILED` | The screenshot file could not be written, or for `logs` on an iPhone, its temporary folder could not be created. | `screenshot`; `logs` on an iPhone |
| `TEXT_UNSUPPORTED` | The text has a character the target cannot type: a control character other than newline and tab. | `text` |
| `ELEMENT_NOT_FOUND` | No node matches. | `tap --text/--id` |
| `ELEMENT_AMBIGUOUS` | More than one node matches. | `tap --text/--id` |
| `ELEMENT_COVERED` | The node's center is under the on-screen keyboard. | `tap --text/--id` |
| `INPUT_BLOCKED` | The device does not let adb inject input; on Xiaomi, Redmi and POCO, "USB debugging (Security settings)" is off; on vivo and iQOO, "USB simulated click". | `tap`, `swipe`, `text`, `key` |
| `INSTALL_FAILED` | The device refused the app. `reason` is Android's code, or simctl's `<domain>:<code>` on a simulator, or on an iPhone the `<domain>:<code>` of the deepest error devicectl reports. For `install-runner`, devicectl's message. | `install`, `install-runner` |
| `UNINSTALL_FAILED` | The device refused to remove the app, or it is an iOS system app (`reason` `SYSTEM_APP`). `reason` is Android's code, or simctl's `<domain>:<code>` on a simulator, or on an iPhone the `<domain>:<code>` of the deepest error devicectl reports. For `uninstall-runner`, devicectl's message, or simctl's on a simulator. | `uninstall`, `uninstall-runner` |
| `APP_NOT_FOUND` | The package is not installed. | `launch`, `terminate`, `uninstall`, `logs` |
| `APP_NOT_LAUNCHABLE` | The package is installed but has no activity a launcher can start. | `launch` on Android |
| `INTERNAL` | A bug in karagoz. Please report it with the message. | all |
